# PhotoCraft algorithm reuse, second source review

2026-10-12. Source review and read-only primary-source retrieval only. No upstream or AFFINT code was executed, built, tested, formatted, benchmarked or copied into product modules. Interaction implementation remains frozen for the coordinator.

The useful extraction is **coverage processing and incremental mask-brush state**, not PhotoCraft's compositor or whole document. Its selection distance transform, flat morphology, deterministic stroke walking, sparse flow coverage and changed-tile restoration are concrete code worth adapting. Its encoded/straight color kernels, quantized mask wrappers, global caches and automatic reduced-resolution segmentation cannot satisfy AFFINT's existing contracts unchanged.

The [distance-transform paper](https://www.cs.cornell.edu/~dph/papers/dt.pdf) supplies the lower-envelope algorithm's linear-work argument. ## Quality, errors and ownership hazards

The selected paint/raster crates forbid unsafe and deny explicit unwrap/expect/panic placeholders. Their modules separate settings, path walking and coverage. Those are useful qualities, not evidence that ordinary indexed slicing or allocation cannot panic. `wand_region` and `Region::at` trust buffer/dimension consistency; guided filtering trusts input sizes and valid epsilon. EDT checks dimensions but returns an empty vector for invalid input. The brush public path sanitizes size/scatter, yet a huge finite distance still drives a distance-spacing loop without a total dab-work cap. AFFINT must reject malformed input and reserve memory rather than clamp it into a different successful edit.

Memory is material: EDT holds a u32 plane and f32 result, **192 MB at24MP /384 MB at48MP**, before seed/input masks, row-band scratch, envelopes and concurrent tasks. Guided-color refinement retains many scalar planes; `box_mean` adds an f64 column prefix plane. `refine_mask_with` collects all tile results and then another full bounding-box output. Large halos can outweigh a 256×256 core. Limit worker count from an admitted peak scratch calculation; stream completed cores to immutable tiles. Radius-bounded operations may compute sufficient halos and saturate distances outside their support, but that needs a separate oracle before replacing the global EDT.

Several source-established gaps rule out cache transplantation:

- [`ops/src/tiles.rs:14`](https://github.com/storytold/photocraft/blob/53d814f6437db8a26d5a469f0f8198ab8f5fb658/crates/ops/src/tiles.rs#L14) still traverses layer surfaces/masks/channels/quick mask, omitting document selection and patterns owned by [`doc/src/lib.rs`](https://github.com/storytold/photocraft/blob/53d814f6437db8a26d5a469f0f8198ab8f5fb658/crates/doc/src/lib.rs). This is a static accounting omission, not a new runtime reproduction.
- [`compose/src/lib.rs:1358`](https://github.com/storytold/photocraft/blob/53d814f6437db8a26d5a469f0f8198ab8f5fb658/crates/compose/src/lib.rs#L1358) hashes content/masks/effects but omits `advanced.transparency_shapes`, which `effect_shape` reads at673. Changing it can leave the region/light key unchanged. Pattern source contents are also consumed without appearing in that key. Cached-versus-uncached minimal fixtures remain coordinator proof work; the historic lost-evidence failure is not claimed rerun.
- Effect entries pin a Layer while charging map arrays; concurrent misses may both build; eviction retains the currently used map even if it alone exceeds the cap. The [combined-mask cache](https://github.com/storytold/photocraft/blob/53d814f6437db8a26d5a469f0f8198ab8f5fb658/crates/compose/src/masks.rs) is better at charging retained input surfaces, rejecting oversized retained results and preventing a pre-purge build from repopulating cache. Still charge in-flight outputs, source capacities and callers surviving eviction. Avoid hash-only equality and global cache ownership.

`combined_mask`'s comment says f32 surface, but its actual format is U16. Refinement `Region` stores U8, and edge-brush instructions store signed i8 coverage. None is an acceptable invisible f32-mask substitution. Effects' `edt_nearest` also retains f32 coordinate-square subtraction, unlike the improved selection kernel. `blur::gaussian` switches to three approximate box passes above radius4; this cannot enter a declared exact Gaussian operation silently. Layer effects, destructive native-channel retouching, RGB decontamination and whole-document composition require separate color/semantics work.

[`segment/mod.rs`](https://github.com/storytold/photocraft/blob/53d814f6437db8a26d5a469f0f8198ab8f5fb658/crates/algo/src/segment/mod.rs) uses straight RGB in0..1, composites transparency over gray and analyzes large images at reduced resolution before full-resolution boundary recuts. That is an explicitly heuristic segmentation scheme, outside this user's current full-resolution fidelity requirement. The original-image residency/chunk-sink GPU ideas remain research; this review does not authorize a GPU backend.

## Proposed AFFINT integration diff, after the UI/lag batch

**Next kernel task:** adapt `edt`/`row_distance` and only `expand`/`contract` first. Keep a private validated `CoverageInput<'a>` borrowing a plane and checked dimensions; a private `MaskWorkspace` owns the admitted `Buffer<u32>` vertical/band costs, `Buffer<usize>` sites and `Buffer<f64>` envelope boundaries. The call returns `Result<Buffer<f32>, Error>`, with cancellation between bounded column/row bands and a checked work charge. Use AFFINT's existing allocation/lease mechanism; no bare Vec-returning public pixel API or new Rayon dependency is required. Initially preserve upstream threshold/ramp behavior exactly, including radius0 not being a general fractional-mask identity. Compare it with independent brute force before changing that policy. Prove the kernel separately from the subsequent source-model/storage change; do not expose a disconnected UI feature.

First land one **nondestructive f32 mask-brush/selection primitive increment**. A private mask-processing module should hide borrowed input, admitted scratch, sparse tiles and deterministic stroke state behind validated operations. Adapt PhotoCraft's round coverage/spacing/RNG subset and EDT; do not depend on its doc/color/raster/engine crates. Retain extraction notices and exact source/function pins. A generic imaging framework is unnecessary.

1. In document `model/staging/validate/session/archive`, introduce a narrow immutable coverage source with finite0..1 f32 samples, exact dimensions and shared tile owners. Charge allocation capacities across live state, gesture, undo/redo, queued snapshots and cache retention; account off-canvas/default owners. No conversion through RGBA8 and no mutation of `RasterAsset` originals. Storage must round-trip coverage/parameters/history semantics before UI integration. This is required supporting work, not a drop-in renderer-only feature.
2. In renderer source evaluation, sample coverage with declared source-pixel centers, transparent border and bilinear semantics. Map scalar coverage to canonical premultiplied white coverage and pass through the existing target-local source transform/ordered crop/exposure/mask/opacity evaluation. Use `MaskMode::Alpha` for painted masks; luminance remains its existing linear policy. Preserve `RenderRequest` dimensions/format and final Frame's sole lease; F32 display/export goldens stay unchanged. Live mask-operation caches must include source identity, ordered prefix, local pixel region/grid, guide dependency and kernel parameters; never key only by viewport or current revision.
3. In the editor's established gesture transaction, keep one pre-stroke coverage snapshot; apply only changed/tail tiles; changed points preview and release commits one edit. Cancellation drops staged tiles and leases. Sparse coverage damage alone does not make the full canvas renderer incremental: separately measure and implement dependency-aware retained evaluation/publication before claiming pointer responsiveness.

Next, adapt octagonal morphology and bounded full-resolution guided refinement. First guide admission should be an explicitly declared original RGBA8 source in matching local coordinates; HDR/evaluated composite guides need a separate color/range policy. Do not demultiply tiny-alpha HDR to a clipped0..1 guide or bake decontamination into original pixels. Crops/exposure remain stored operations, with filtering order and finite support defined before insertion into the live-operation enum.

Coordinator acceptance should cover three coherent groups: independent small-mask brute force/naive morphology plus6000/8000-coordinate boundaries; analytic dab/flow values, arbitrary event chunking, tail preview/commit equality, one undo and cancellation preserving original owners; and24/48MP cold/warm peak-byte/time probes including admitted halos, concurrent miss work, source retention after dropping old snapshots, masked transforms/crops/exposure and all existing renderer goldens. Report actual pointer-event-to-present wall timing separately from kernel throughput. No speed, compatibility or fidelity guarantee is established by this source review.
