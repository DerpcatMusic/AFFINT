# VectorCraft algorithm reuse, second source review

2026-10-12. **Source review only; no behavior was executed or reproduced in this review.** No builds, Cargo commands, tests, formatting, benchmarks, runtime helpers or desktop operations were performed. No installed Affinity window or raw proprietary decompiler output was inspected. Relevant context is the repository contract, product/domain/architecture/work log, `reuse-candidates.md`, `photocraft-reuse-r2.md`, and the sanitized `affinity-behavior.md`. Rust best practices, codebase design and domain modeling inform the proposed interface; this report changes no product module or shared document.

The strongest reuse is a **small, fallible curve-boolean geometry module**, followed by shared stroke geometry and snapping/gradient mathematics. VectorCraft's editor, renderer, mutable document, JSON command catalog and broad effects crate should remain references. They are not substitutes for AFFINT's atomic transactions, immutable source ownership, linear F32 renderer or faithful installed-reference UI.

`vectorcraft-pathops` depends on `vectorcraft-geom`, Kurbo, linesweeper and thiserror. ## Numerical and error-policy findings

**V1 — Error and empty-set ambiguity is established by source.** [`boolean.rs:628–700`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/pathops/src/boolean.rs#L628) returns empty geometry on `boolean`/`normalize` errors, returns empty for `boolean_n` arrangement failure, silently skips an operand whose normalization fails in `unite_all`, and reports area zero on failure. A valid empty intersection and failed geometry are thus indistinguishable at these interfaces. `try_boolean` is the correct starting seam, but validates neither finite positive `precision` nor finite derived output. The `Arrangement` constructor catches a sweep panic; `normalize_bez` directly calls the sweep without that guard. Panic catching is neither an allocation limit nor a guarantee under abort-on-panic. AFFINT must propagate structured errors and preserve operands/history, not interpret failure as successful empty art.

**V2 — Cleanup deliberately removes real thin artwork; this is an analytical source consequence, not a run.** [`boolean.rs:350–375`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/pathops/src/boolean.rs#L350) drops any contour with `2 * abs(area) / perimeter < precision`. A valid 100-by-0.001 rectangle has area 0.1 and perimeter 200.002, giving mean width about 0.001, below default 0.01; if emitted as that contour it is removed. A legitimate tiny hole can be removed too. This is not only numerical debris and cannot be AFFINT's hidden exact-output policy. Retain nonzero contours, or return numerical ambiguity if the algorithm cannot distinguish them safely. A user-selected simplify/cleanup operation can use a separately named tolerance.

**V3 — “Curve preserving” is qualified.** [`boolean.rs:133–221,249–278,490–623`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/pathops/src/boolean.rs#L133) establishes an absolute-coordinate-derived sweep epsilon with floor `1e-6`, snapping near-horizontal anchor/handle heights, approximate nearest-point reconstruction and sampled fallback fitting (12 samples per segment). Original anchor retention and repair tests are valuable; sampled residual acceptance is not a continuous Hausdorff certificate. Translation changes tolerance because it depends on absolute coordinates; `1e-6 * (1 + coordinate magnitude)` used for curve matching can dwarf the requested 0.01 refit precision far from the origin. Finite input also does not guarantee finite intermediate sums/products. Rebase/normalize into a local numerical frame, validate computed epsilon/output and state distinct topology/refit tolerances. Do not claim exact symbolic geometry or a proven global error bound.

Upstream comments and regression tests describe a linesweeper 0.5 contour-piece/lens issue (`#1028`) and the near-horizontal ordering repair. Those establish acknowledged upstream failure classes and intended fixes; their actual effectiveness at this pin was not executed here. AFFINT should preserve these fixtures and add independent area/winding/error oracles, not merely assert an anchor count.

`fit.rs:50–66` limits recursive fitting depth but emits the current fit once depth exceeds 40 even if its sampled error still exceeds tolerance. `warp.rs:46–92` caps each art edge at 4000 subdivisions while retaining the stated maximum mapped-segment comment. Both need an explicit fidelity-limit error if used for exact requested output.

**V4 — Divide/Shape Builder limit changes behavior.** [`planar.rs:307–352`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/pathops/src/planar.rs#L307) falls back to filled regions beyond 4096 segments or when a planar map cannot be obtained. Fresh `pathfinder.rs:103–114` routes open-path Divide through this result. Cutting edges can stop cutting without an error. Preserve this as an explicit `ComplexityLimit`/`NumericalAmbiguity` outcome; a count cap is not a byte cap.

## Stroke, brush, snapping and ownership findings

**V5 — Brushed artwork can be wrongly culled.** [`brush_fx.rs:58–66`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/render/src/brush_fx.rs#L58) inflates the ordinary node bound by `16 * stroke_width + 8` without consulting the referenced brush. A legal round calligraphic size 1296 and stroke weight 1 has radius 648, while the added pad is 24. Put its centerline hundreds of points outside the viewport and its nib can contribute visible art while [`Renderer::skipped`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/render/src/lib.rs#L858) rejects the node using that bound. This establishes a nonconservative bound and reachable skip path; no screenshot/pixel reproduction was made. Bounds must depend on brush revision and generated art/support, with safe overestimation when tight bounds are unavailable.

**V6 — Brush limits truncate successful output.** [`warp.rs:203–246,333–364`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/brush/src/warp.rs#L203) stops scatter after 20,000 instances per track and pattern after 20,000 tiles per run. Pattern fitting first computes scale/spacing for the uncapped count, then emits only its prefix. Large legitimate strokes therefore lose artwork rather than report a limit. Multiple tracks/runs and complex art multiply the allocation despite these local caps. `warp_node:20–43` silently drops text, images and symbol-instance art. Library parsing skips malformed entries and sanitizes numbers; unknown renderer brush names fall back to a plain stroke. AFFINT needs explicit unsupported/malformed/resource outcomes and retained opaque imported data or restricted save, not silent substitution/removal.

`track.rs:185–235` offers deterministic RNG, but hashes quantized coordinates and brush name to derive the seed. Editing/translating a path or renaming a brush can reseed its appearance; repeated similar paths can share variation. This is an upstream choice, not automatically a bug. Persist a stable `StrokeSeed` and a algorithm version if AFFINT expects variation to survive ordinary edits, undo and save. `Track` exposes its arrays publicly while `frame/in_out` assume nonempty equal-length internal invariants. Extract it as a private validated implementation, not an externally constructible bag of arrays. Arc-length track flattening and nib samples do not alone certify pressure fidelity between samples.

**V7 — Snap target cap is not enforced within a large path.** [`guides.rs:325–353`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/tools/src/guides.rs#L325) checks `budget == 0` before a node, then visits every anchor of that path while saturating the budget. One path can exceed the advertised 20,000 anchor cap; drawing mode also adds x/y target arrays for each anchor. By contrast `push_paths:212–220` actually uses `take(anchors)`. The traversal is recursive, artboard/bounds entries are separate owners and item counts do not cap bytes. Adapt the useful sorted query/gesture key with a checked global byte limit, bounded traversal and deterministic limit/error policy. SnapKey includes revision, exclusions, view and construction options; retain that completeness and measure gathering/query latency later.

**V8 — Gradient ownership needs stable identity.** [`engine/cmd/gradient.rs:75–98`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/engine/src/cmd/gradient.rs#L75) tags a selected stop with active **tab index**, first selected node, fill/stroke and appearance-item index. `engine/src/lib.rs:1256–1268` removes a tab and reuses its index; reset/deactivation does not explicitly clear stop/freeform ownership. An existing selected node in another document with the same document-local NodeId can therefore match the old owner after tab removal. This is a source-established identity gap, not an executed user interaction. Paint replacement and stop reordering also require a deliberate selection policy. AFFINT should use document incarnation, NodeId, stable paint-slot identity and StopId/paint revision, and invalidate or remap in the same edit.

The pure gradient math is worthwhile. Keep linear-light interpolation, alpha handling, finite geometry and duplicate-offset discontinuity policies explicit in AFFINT. The upstream sample test's mid value 0.5 in its RGB representation is not evidence that direct adoption matches AFFINT's working-color policy. Gradient transform/stop operations currently accept public scalar fields and use default fallbacks; external input validation and minimum spacing/tolerance cannot be inferred from the functions alone.

## Dirty dependencies, cache correctness and resources

**Positive pattern:** retaining `Arc<Node>` alongside a pointer key avoids address reuse for that node allocation. Geometry can remain cached across structurally shared snapshots. Brush entries additionally compare the whole path/stroke and parsed brush definition, and refresh the library when its JSON source changes. This is better than hashing a brush name alone. Rust's actual [Arc contract](https://doc.rust-lang.org/std/sync/struct.Arc.html) provides shared ownership, not automatic inner-data thread safety; it implements Send/Sync only with suitable inner types.

**V9 — Stroke-gradient cache omits a construction dependency.** [`render/lib.rs:1376–1403`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/render/src/lib.rs#L1376) keys slices by stroke address plus `floor(log2(px * 0.25))`, but calls `gradient_slices` with exact `px + tol` margin and exact `px` growth. Pixel scales 1 and 1.5 share bucket -2 yet generate different geometry. `effects/stroke/gradient.rs:274–295` uses both margin and growth. Thus the key is source-proven incomplete; whether clipped pixel output differs for a given fixture is **unreproduced**. Key the exact semantic values or generate all slice geometry from the same canonical bucket parameters. Compare sequential same-renderer zooms with a new renderer at each scale, including translucent gradients and corners.

**V10 — Live text expansion omits font generation.** [`render/live.rs:54–100`](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/render/src/live.rs#L54) keys expansion by live-node identity and symbol/pattern resource hash. `effects/live.rs:18–45` and `effects/reshape.rs:33–52` outline text using global FontDb. `render/lib.rs:1483–1487` clears only the ordinary text cache when FontDb generation changes. An unchanged text envelope or text-containing Pathfinder expansion can retain old outlined text. This is a source-established omitted dependency; no font-loading/pixel run was performed. Add font-generation/resolution identity to the dependency key and independent cached/uncached proof. The resource hash stores raw symbol/pattern addresses without retaining an explicit token for those source allocations; transformed output clones do not prove all original resource allocations are pinned. Address-reuse/transitive-resource cases require a separate ownership audit, not an asserted reproduced ABA failure.

The fresh [FrameCache](https://github.com/storytold/vectorcraft/blob/885a6e38cdc2b788581978be6c39a9114f12af67/crates/render/src/lru.rs#L62) is useful LRU logic: it refuses an estimated oversized entry, evicts older-frame entries and avoids evicting entries used in the current frame. However:

- Geometry, stroke outlines, stroke slices, shadows and live-effect geometry in `render/lib.rs:589–609` still prune primarily by entry count/age. One complex path/slice set can be large.
- `lru::node_bytes:186–195` estimates node/path storage; it does not count full paint/appearance data, arbitrary strings/resources, vector spare capacity or every pinned source subtree. Brush accounting omits parsed-library JSON/brush-art residency. Evicted outputs held by callers remain live. These are accounting scope gaps, not measured leaks.
- `FrameCache::insert` receives an already-created value. Its budget cannot bound generation scratch, the candidate and retained output concurrently. Its byte additions and counters also use ordinary arithmetic rather than checked admission.
- Cached bounds need every external dependency that can change their support, such as brush definition changes. A node-only pointer key is insufficient for document-owned resources.

AFFINT should use a retained budget lease for every live output allocation, including worker handoff, history and cache owners, and separately account scratch/candidates. Dirty dependencies should expose typed content/resource generations, ordered operands and transforms. A cache key is a semantic contract, not simply a fast hash; digest collisions or omitted inputs need independent equality/identity checks. No source comment about profiling, cache speed or structural sharing establishes an AFFINT performance result.

## Next implementation kernel: bounded binary live-boolean evaluation

Implement one module with a small interface in the existing toolkit-independent render/geometry area first; another wrapper crate is unnecessary. Start **two filled operands, Union/Intersect/Difference/Xor**, with explicit NonZero/EvenOdd rules. Keep Shape Builder, multi-input style inheritance, brush expansion and broad effects out of this increment. The following is an interface sketch, not compiled implementation or a new dependency commitment:

```rust
pub enum BooleanOp { Union, Intersect, Difference, Xor }
pub enum FillRule { NonZero, EvenOdd }

pub struct BooleanSpec { /* validated op, topology tolerance, schema version */ }
pub struct FilledPath<'a> { /* borrowed validated path, rule, local transform */ }
pub struct GeometryWork<'a> { /* byte admission, limits, cancellation */ }
pub struct EvaluatedPath { /* immutable BezPath + result lease + quality receipt */ }

pub fn evaluate_boolean(
    spec: &BooleanSpec,
    operands: [FilledPath<'_>; 2],
    work: &mut GeometryWork<'_>,
) -> Result<EvaluatedPath, GeometryError>;
```

Private constructors validate finite bounded geometry, finite positive tolerances, transforms and supported path starts; checked arithmetic computes reservation sizes. `GeometryError` distinguishes invalid input, unsupported geometry, numerical ambiguity, complexity/byte limit, cancellation and backend failure. Empty geometry is a successful typed empty set, never an error sentinel. `EvaluatedPath` exposes a borrowed path and quality/resource receipt; cloning a handle shares the same immutable output and charge. Input borrows last only for the call; queued jobs retain committed snapshots rather than borrow UI data. Do not claim a type is Send/Sync merely because it is Arc-owned.

Use linesweeper 0.5.0 `Topology` through a qualified adapter and adapt VectorCraft's contour/original-curve reconstruction where justified. First preserve native returned subcurves without least-squares merging; compact anchor counts are secondary to fidelity. Keep source curve/segment provenance where possible. Do not drop positive-area slivers. Translate into a local numerical frame before topology and validate restoration/output. Explicit quality receipts identify algorithm/version, tolerance in document units and the certified or empirically qualified bound; do not call sampled refitting a certificate. Continuous curve-error checking needs stronger bounds than a fixed sample grid before enabling simplification in this kernel.

The document integration is a separate atomic step after the geometry gates. A live boolean must own an ordered pair of operand relationships, stable NodeIds and retained original paths/transforms; output is a derived evaluation. A compound container with ordered operand children is a viable first representation and reduces external-reference/double-paint ambiguity. Visibility of retained operand artwork, local coordinate frame and style owner must be explicit. Use the sanitized behavior specification's lowest-object style as the initial desired policy, without claiming installed runtime verification. Release restores operand identities, order, transforms and prior properties. Expand/bake is a distinct transaction. Existing parent/mask cycle validation must include any new geometry dependency edges; no document method exposes mutable geometry to the UI.

### Acceptance gates for the coordinator

1. **Fidelity:** disjoint/overlapping/nested analytic rectangles; holes and opposite winding under both input rules; open fill closure; cubic/quad crossings and tangencies; coincident curves; zero-length segments; very thin real solids/holes; repeated operations; translation/scale and tiny/large coordinates. Use analytic area/membership for suitable fixtures and independently qualified geometry/raster references for curves. Preserve original path bits/control handles; output remains Bézier geometry. Every declared tolerance has a continuous bound or an explicitly bounded qualification corpus, never a self-round-trip-only oracle.
2. **Atomicity/undo:** create, change operation, move an operand, release and explicit expand each commit once through Session. Undo/redo restores identities/recipe/source paths and source-sharing; branch-created identities remain fresh. Cycles, unsupported sources, ambiguity and limits leave committed snapshot, revision and undo/redo untouched. Cancel a preview at every phase; no hidden partial operand deletion or overwritten style.
3. **Resources/cancellation:** cap source elements, input copies, events/intersections/splits, output capacity and all scratch/retained owners by checked bytes. Budget refusal must happen before the violating allocation and release all candidate charges. Cache hits and misses obey the same admission policy. Cancellation checkpoints inside sweep/extraction have an observed maximum latency on recorded hardware; stale job results cannot publish. A synchronous dependency call with no audited bound fails this gate.
4. **Dependencies/cache:** cache key includes both operand identities/content generations, fill rules, ordered local transforms, op/precision/schema/algorithm version and every applicable resource revision. Geometry evaluation is independent of output zoom; render coverage caches separately key exact raster/view/color/quality inputs. A moved/changed operand invalidates its boolean and downstream mask/bounds/coverage; unrelated paint edits do not recompute topology. Cached and uncached outputs agree. Persist recipe/originals, not a view-dependent approximation as source.
5. **Workflow:** a real select-two-shapes/create-live-boolean/edit-operand/release/undo/native-save/reopen/exact-export scenario through the same document interface. UI exposes enabled actions only after that path is implemented, and installed-reference UI matching is separately owned. No performance/parity assertion follows from passing headless geometry tests.

Suggested coordinator regressions before any upstream reuse: 100-by-0.001 rectangle and tiny hole; one snap path with more than 20,000 anchors; round nib size 1296 centered outside a view but overlapping it; scatter/pattern requiring 20,001 copies; same-renderer along/across gradient at pixel scales 1 then 1.5 versus fresh renderers; font-generation change inside a text envelope/live Pathfinder; and two document tabs with matching local NodeIds then tab removal. These are concrete proof requests, **not tests run or passing claims**. Root should assign implementation/test file ownership and use its serialized `scripts/verify` lane once a bounded meaningful increment is ready.

The next useful increment is the binary kernel plus retained-operand transaction workflow once those gates pass. Plain editable strokes can proceed using already-pinned Kurbo while boolean resource/cancellation qualification is resolved. Neither path requires adopting VectorCraft's broad compositor or UI.
