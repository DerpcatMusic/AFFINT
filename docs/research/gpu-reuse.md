# Shared-wgpu document acceleration: focused reuse audit, round 1

2026-10-12. **Source audit only; no implementation, build, execution of upstream/product code, tests, advisory scan, or performance measurement by this worker.** Five upstream families inspected: PhotoCraft, Graphite, Vello, wgpu, Kurbo. No nested agents or restricted vendor evidence were used.

## Decision

**Keep wgpu 29.0.4 + Hybrid/common 0.2.0. Implement a small AFFINT-owned f32 linear-premultiplied raster evaluator on the existing device; do not transplant a photo editor or node-graph executor. Keep the established CPU coverage policy for its first slice.** Reuse wgpu's resource/command/completion APIs, Kurbo's geometry, and Hybrid's final texture presentation directly. PhotoCraft supplies useful residency/chunk-sink/planning ideas, not a compatible compositor to import.

There is an important middle option before writing another coverage rasterizer: **`vello_common 0.2.0` publicly exposes CPU-generated coverage strips**, including a low-level entry that can consume AFFINT's already finely flattened lines. It needs neither a fork nor GPU readback. It is **not a public float-coverage GPU kernel**, and its coverage formula, u8 quantization and numeric/work limits must pass independent oracles before replacing current coverage. Default Vello curve flattening must not replace AFFINT's much finer geometry policy. [V2, K]

**Answer to the crate question:** public wgpu exposes float working textures, caller-controlled encoding and GPU completion without a fork/readback. Public Hybrid exposes the same-device final-image seam. Common exposes CPU u8 coverage. **None of the inspected high-level renderers supplies the complete AFFINT linear-premultiplied/HDR/transform/mask/isolation/bounded-retirement contract as a drop-in public wgpu29 interface.** This is a bounded finding, not a claim about every graphics crate. Domain-specific *operation* kernels are justified; reimplementing GPU access, Bézier flattening, codecs or a full vector engine is not. [W, V1–V4, P, G]

## Concrete source findings

### 1. PhotoCraft: borrow three ideas, not its color kernels

- **Original-source residency:** pages contain COW raster tiles; matching tile identity avoids uploads. `TexKind::Rgba8Direct` preserves original RGBA8 uploads. Separate mask/source roles and LRU pages are useful ideas for immutable asset IDs plus device generation. Pointer keys require pinned owners; AFFINT must also distinguish source format/color policy. The default resident allowance is4GiB plus1.5GiB effect cache, unsuitable as AFFINT policy. [P: `lib.rs:6–26,60–83,123–156,659–674`]
- **A bounded chunk sink:** `Compositor::encode` records into the caller's encoder; `ChunkOut` borrows a reusable float chunk. Its consumer must record a copy/pass **before reuse**, not retain a view as a completed persistent frame. `render` also submits between large batches and waits for previous native submissions; return means submitted, not completed. `encode` deliberately cannot publish prefix checkpoints because its caller could discard the command buffer. This ownership distinction is worth adopting independently. Its stated memory budget covers pages/caches, not all output/staging/scratch/in-flight owners. [P: `lib.rs:86–92,824–860,910–916,938–989`]
- **Ordered passes and isolation:** a tree-to-pass plan, abstract scratch slots and indivisible group/prefix dependencies are a useful scheduling pattern. It is a large PSD-oriented planner, not a small AFFINT graph interface. Start without its effects/blend-mode/prefix machinery. [P: `plan.rs`; `lib.rs:1124…`]

**Precision/semantic blockers:** chunk pixels are **straight alpha**, not AFFINT's premultiplied contract. RGBA8 content uses direct UNORM loads; ordinary source-over computes on those channel values, without a general source-linearization step. Exposure has distinct integer-depth clipping and HDR behavior. SourceRGBA32F is assigned a **RGBA16Float** upload kind: full-float accumulation does not recover precision already lost on upload. Source loads are document-coordinate texels, not AFFINT's arbitrary inverse-affine bilinear sampler. Vector masks are described as rasterized mask inputs, not an exposed general GPU coverage kernel. These are specific interface differences, not allegations that PhotoCraft violates its own policy. [P: `lib.rs:123–147,1898–1932`; `compose.wgsl:1–6,261–277,552–561,765–806`]

### 2. Graphite: compatible device family, wrong small-module boundary

`wgpu-executor` does retain GPU rasters and reuse textures, but its per-pixel adjustment pipeline fixes the output target to **`Rgba8UnormSrgb`**. CPU-to-GPU raster conversion likewise requests that format. Accepting a `Raster<GPU>` is not evidence of preserving an HDR float intermediate. Replacing those assumptions requires raster types, shader-generation/runtime and graph semantics work, not just changing a format constant. [G: `texture_conversion.rs:11–30`; `shader_runtime/per_pixel_adjust_runtime.rs:66–176`]

The texture cache's `max_free_bytes` counts **unshared/free cached textures**, not active shared rasters, pending output or GPU retirement. A shared/weakly-shared owner distinguishes application reuse; it is not itself a queue-completion fence. Useful pooling ideas must remain separate from admission and completion. Prefer public wgpu completion over importing Graphite's executor/IO/dynamic node framework. [G: `texture_cache.rs:19–98`; `wgpu-executor/Cargo.toml`]

### 3. Vello: public presentation and public CPU coverage are different seams

**Hybrid0.2:** `TextureBindings::insert` accepts a float-sampleable non-array2D view with `TEXTURE_BINDING`, using an **unfilterable** float binding and mip0. `Renderer::render` takes the caller's device/queue/encoder. These are genuine no-fork/no-normal-readback APIs. A root target format is configurable; **that does not make its complete graph float**: atlas/layer/scratch boundaries areRGBA8, paints are packedRGBA8, and path coverage is byte storage. Keep Hybrid after AFFINT's final display encoding rather than using its masks/filters/groups as photo working operations. The existing diagnostic half-float display proof is not document evaluation. [V1]

**Common0.2, a small concrete coverage candidate:** `StripGenerator`, `StripStorage { strips, alphas: Vec<u8> }`, `Tiles::make_tiles_analytic_aa`, `strip::render`, and `visit_strip_fill_segments` are public. `strip::render` consumes public flattened `Line` values and caller-owned vectors. Therefore an isolated CPU-coverage adapter can reuse AFFINT's global Kurbo1/1024-output-pixel flattening, convert to block-local lines, build/sort tiles, generate strips and upload only coverage. This bypasses Common's private fixed **0.25-pixel** curve tolerance without a fork. It does **not** turn preprocessing into a GPU coverage kernel. [V2]

Limits: u16 viewport geometry, f32 line arithmetic, i16 coarse winding, a hard line-index bound, and buffers that grow internally. The source explicitly warns about pathological winding and over-limit lines; one loop takes only the maximum line count. Admission must reject excess work rather than accept silently missing segments. Coverage is formed from accumulated signed area and quantized to u8; it is not the current explicit supersample definition or arbitrary f32 coverage. Disjoint opposite-winding contours within one pixel are a required counterexample: absolute integrated winding is not generally the area where winding is nonzero. Enclosing holes/left-of-view winding and block seams also need proof. **Do not switch production coverage merely because this entry is public.** [V2: `tile.rs:39–53,539–559`; `strip.rs:453–505,584…`]

**Current GPU0.3/classic0.11:** current GPU still CPU-preprocesses coverage into byte strips and carriesRGBA8 intermediate boundaries; classic's public render-to-texture contract explicitly requiresRGBA8UNORM. Both require wgpu30 in the inspected manifests. Float arithmetic *inside* a shader does not establish float storage between passes or a public coverage-only float output. No framework fork/upgrade is recommended for this slice. [V3, V4]

## Precision and byte admission: explicit choices

Separate texture storage read/write capabilities and binding limits still apply. | First fidelity target. Use separate input/output resources and bounded tiles/slots; never silently downgrade. |
| RGBA16Float working tile |8B/pixel; 1024² =8MiB; dense24MP =192MB | Float16 *storage* does not require WGSL `f16` arithmetic; arithmetic may remainf32. | Original RGBA8 source / final RGBA8 display |4B/pixel; dense24MP =96MB | Non-sRGB UNORM loads allow explicit decode; final display encoding must follow the established non-sRGB surface policy. | Source bytes stay immutable at original resolution. [W: `wgpu-types/src/texture/format.rs:922–990,1039–1102,1241–1244`; `features.rs:1690–1708`.] Float representation facts are numeric constraints, not measured visual quality. Baseline format tables are not permission to skip actual adapter/device validation.

Even **one** dense24MP f32 texture exceeds the app's current96MiB canvas partition. Dense working source/output duplication is not viable under that partition. Tiled source residency and tile scratch avoid dense float frames, but output, old accepted frame, new candidate frame, staging and submitted-but-not-retired owners still count. An exact large finalRGBA8 candidate plus source/scratch may also exceed96MiB. Root must select an explicit larger admitted partition, a tiled exact output/export path, or a truthful budget refusal—never reduce resolution or quietly evade the cap. Surface and Hybrid private resources remain separately accounted, as ADR0005 already states.

## Recommended first vertical slice

**One exact requested-region job: originalRGBA8 raster(s) → affine linear-premultiplied sampling → crop/exposure/mask/opacity → isolated source-over group → final display texture on the existing shared device.** Include an existing CPU-generated vector mask in the fixture; do not make GPU vector rasterization a prerequisite. This is one bounded feature path, not general HDR/ICC/editor parity.

1. Admit immutable source pages by asset identity/format/color policy/device generation. Upload original bytes only when absent; do not upload the CPU-rendered full frame for this accelerated job. Decode each bilinear tap to linear and premultiply **before interpolation**. Respect half-pixel source centers and transparent out-of-source taps; independently reproduce AFFINT's existing u8 decode/LUT values instead of assuming hardware filtering or repeated nonlinear powers match them.
2. Follow existing evaluation order and coverage semantics. Raster sampling happens before live operations; crop multiplies the already-sampled result's output coverage, rather than deleting/clamping source taps. Exposure multiplies premultiplied RGB while retaining alpha/highlights. Masks multiply **all four channels**; luminance means clamped linear premultipliedRGB dot(0.2126,0.7152,0.0722), then optional inversion. A mask dependency ignores normal-page visibility and normal ancestors, but uses the masked layer's dependency-local placement and its own operations. Preserve group isolation: compose children into transparent group scratch, then group operations/mask/opacity, then parent source-over. [A]
3. Retain current canonical coverage blocks/global fine flattening and CPU-produced byte coverage for crop/vector masks. Changing coverage generation is a separate fidelity decision. If public Common coverage fails the agreed oracles, the smallest justified GPU coverage work is evaluation of already-flattened bounded geometry under the declared coverage policy—not a hand-written new curve flattener or general graphics framework.
4. Use admittedRGBA32Float tile intermediates, bounded group depth/work, and no speculative generic graph executor/prefix cache. Validate numeric and affine ranges conservatively; unsupported f32 coordinate accuracy or potential overflow/underflow must produce an explicit CPU fallback/refusal, not success with NaN/zero pixels. A GPU scalar error-status readback, if required later, must be disclosed separately; this proposal promises no routine **pixel** readback, not free correctness checks.
5. Encode final displayRGBA8 once, then present through existing Hybrid bindings. Preserve final full requested dimensions. Do not hand float working color to UI image/effect atlases. Export/test readback is a named separate consumer; ordinary display uses same-device textures.
6. Publication carries revision, exact view/precision, serial, and device generation. Keep the old accepted frame until the candidate is valid; never expose a mixture of revisions from partial chunks. Register retirement after the last submission referencing an owner, including later UI sampling. `Queue::on_submitted_work_done` is public and requires submit/poll servicing; callbacks must be short. `submit` return, CPU cancellation, dropping a cache entry and accepting a new revision are **not GPU completion**. Keep leases charged until completion/device-generation teardown; bound running/pending/output and submitted retirement queues separately. [W: `queue.rs:256–305`; ADR0005]

### Counterexamples and coordinator acceptance oracles

These are proposed verification gates, **not executed results or relaxed existing tests**:

- **Sampling:** an opaque red texel beside transparent blue with nonzero hiddenRGB, half-pixel translation, rotation/shear and source/page-boundary taps. Compare identity/edges to independently computed linear-premultiplied four-tap values; encoded-space or straight-alpha interpolation must fail. Include large coordinates/ill-conditioned transforms to exercise explicit refusal/fallback.
- **HDR/storage:** chain positive and negative exposure so a highlight goes above1 then returns below1; also test tiny alpha, repeated group stores, values near65504 and output-code rounding boundaries. Compare float working pixels to the retainedCPU/f64 analytic operation oracle before final clipping. A matchingRGBA8 display alone cannot prove retainedHDR or half-float suitability.
- **Masks/crops:** alpha vs linear-luminance masks, inversion after clamping, hidden mask nodes, parent transforms that must not enter dependency evaluation, and affine antialiased crop boundaries. Test crop-after-sampling versus the deliberately wrong cropped-source filter result. Changing any semantic input must change the relevant cache identity; unchanged sources must retain upload identity.
- **Isolation:** overlapping opaque children inside a group at0.5 opacity. Expected opacity applies once to the isolated composition; per-child opacity produces a different overlap. Include nested masks/groups and ordered operations, not a flat opaque-only scene.
- **Coverage:** retain current finer/analytic quadratic-area oracle and exact color-tile agreement. Add opposite-winding disjoint contours within a pixel, enclosing holes, fractional transforms, global/block boundary curves and fully offscreen shapes. Compare whole-span vs differently partitioned evaluation. A common mistake is accepting an analytic signed-area formula as the true nonzero/even-odd area for every self-overlap.
- **Ownership/publication:** cancel before encoding, after submission and after completion; complete revisionN afterN+1; replace/device-loss while textures are sampled; deliberately exceed source/scratch/candidate/retired-byte budgets. Verify old valid frame preservation and no early lease release. Tests may read back controlled output; production presentation must not gain a hidden round trip.

For fixtures within the existing declared scope, retain **≤1 output code** fidelity gates and exact partition/cache agreement where currently required. Root should state an additional *working-float* tolerance before enabling GPU output, and compare to independent mathematical fixtures, not only matching CPU/GPU copies of the same kernel. Native adapter/driver/features and test readback scope must be recorded. No measured GPU speedup or world-performance claim follows from this audit.
